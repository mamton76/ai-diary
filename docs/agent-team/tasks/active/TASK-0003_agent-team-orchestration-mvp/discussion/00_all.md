## Вопрос

Как не допускать одновременной выдачи одного TASK-NNNN Claude и Codex при работе в разных ветках?

## Контекст

16 ноября 2026 обнаружен реальный конфликт: Claude создал TASK-0002_review-file-format-save в PR #13 (ветка review/07-file-format), пока ChatGPT предложил тот же номер для оркестратора. Ветка docs/next-clarifications — другая параллельная работа Claude, не связанная с оркестратором.

## Обсуждение (смысловая сводка)

пользователь — агенты не должны независимо выдавать один и тот же номер. Предложен центральный оркестратор, который создаёт задачи в master.

ChatGPT — выделить отдельную узкую роль Task Registrar. Сначала уникально резервировать ID в master, только потом поручать техническую работу агенту; создание draft не означает разрешение начинать разработку. Вначале регистратор работает вручную через GitHub Actions, без подключения облачного запуска Claude/Codex. В дальнейшем запросы могут поступать от адаптеров других сервисов, не меняя переносимого файлового формата.

## Техническое решение на проверку

- Единственный путь выдачи нового ID — скрипт регистратора с registry.json и обязательным уникальным request_key.
- Все присвоенные ID, в том числе из ещё не влитых PR, учитываются в master. Для TASK-0002 создаётся reservation на PR #13. TASK-0003 — bootstrap текущего PR.
- В GitHub Actions разрешён только отдельный ручной workflow_dispatch на master. Конкурирующие вызовы сериализуются через очередь; запись в master делается только fast-forward push, с retry после изменения head.
- Критерии задания и разрешение на запуск отделены от записи задачи (draft не запускает агентов).
- GitHub — adapter, а registry.json и task.md остаются переносимыми; при смене платформы можно перенести скрипт регистрации и файлы.
- Если branch protection запрещает push от GITHUB_TOKEN — fail safely, настраивать отдельные разрешения только с согласия владельца, не пытаться обходить.

**Решение:** центральный регистратор ID выбран как первая часть оркестратора; код и точные права подлежат ревью, до merge автоматизация не действует.
