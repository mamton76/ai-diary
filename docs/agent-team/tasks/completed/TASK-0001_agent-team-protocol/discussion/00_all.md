## Вопрос

Как организовать совместную разработку AI Diary силами Claude Code Cloud и Codex Cloud и как показывать результат пользователю?

## Варианты

1. Локальные CLI-агенты и локальный оркестратор.
2. Собственный постоянно работающий сервер.
3. Штатные облачные среды Claude/Codex с GitHub как интерфейсом и тонким оркестратором.

## Контекст и evidence

Обсуждение 8–15 ноября 2026: пользователь предпочитает облачную работу и готов получать суммаризированное общение агентов через GitHub. Окончательные API/интеграции ещё не реализованы и должны быть проверены отдельной задачей.

## Обсуждение

пользователь — выбрана облачная разработка, GitHub достаточен как интерфейс, если доступны понятные сводки обсуждений.

Предлагаемая реализация — роли Planner, Developer, Reviewer, QA и Orchestrator логические; независимый reviewer получает diff и исходные критерии. Отдельный UI не обязателен на старте. Контроль итогового merge остаётся у пользователя.

**Решение:** [принято] (2026-11-15) Документировать cloud-first команду Claude + Codex, GitHub как интерфейс, независимое ревью, переносимые итоги и контроль решений пользователем. Не объявлять облачную автоматизацию действующей до реализации.

## Вопрос

Как хранить историю вне зависимости от GitHub и поддерживать документацию проекта актуальной?

## Варианты

1. Хранить задачи только в GitHub.
2. Вести полные задачи и важные обсуждения в репозитории; GitHub использовать как внешний интерфейс.

## Контекст и evidence

Обсуждение 15 ноября 2026. Требование не зависеть от GitHub, при этом сохранить удобство GitHub Issues/PR как транспортной интеграции.

## Обсуждение

_Режим изменён на voice-summary (2026-11-15, ревью PR #10): реплики ниже — смысловая сводка, а не дословная запись._

пользователь — задачи должны оставаться в репозитории; обновление проектной документации должно входить в каждую задачу.

пользователь — discussion является папкой отдельных тредов с файлом их конкатенации.

пользователь — название папки задачи должно содержать номер и краткое описание.

Предлагаемая реализация — формат TASK-NNNN_short-description; canonical task.md и discussion/threads/*.md; генерируемый 00_all.md; result.md; активные и завершённые задачи разнесены. Documentation Impact проверяется на всех этапах.

**Решение:** [принято] (2026-11-15) Repository-first задачи с переносимой историей, отдельными тредами и конкатенацией; папки с ID и slug; Documentation Impact — обязательный gate Definition of Done.
