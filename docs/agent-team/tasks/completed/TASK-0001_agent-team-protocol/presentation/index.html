TASK-0001PR #10черновик презентации

Протокол команды Claude + Codex

Как агенты берут задачу, обсуждают, проверяют друг друга и отдают вам результат — и что из этого уже работает, а что пока только описано.

Зачем эта задача

Проблема

Агенты работали в отдельных сессиях. Договорённости оставались в чатах, итог надо было собирать вручную, а ревью одного агента другим ничем не было оформлено.

Что хотели получить

  • история задач живёт в репозитории, а не только в GitHub;
  • у каждой задачи есть план, проверки и итог;
  • независимое ревью и Documentation Impact обязательны;
  • вы получаете короткую сводку, а не переписку агентов.

Чего задача не делает

Не запускает облачных агентов автоматически, не выдаёт токены, не подключает события GitHub и не меняет продукт AI Diary.

Роли

Product Owner — вы

Ставите цель, утверждаете продуктовые и архитектурные решения, решаете споры агентов, разрешаете merge и deploy.

Planner / Architect

Claude или Codex. План, acceptance criteria, Documentation Impact, открытые неопределённости.

Developer

Обычно Claude Code Cloud. Ветка, код и документы, тесты, diff и логи.

Independent Reviewer

Обычно Codex Cloud. Получает исходную постановку и diff, а не самоотчёт разработчика. Автор не утверждает своё ревью.

QA

Роль, не обязательно отдельный агент: сверяет критерии с реальными результатами CI и тестов.

Обсуждения: отдельные треды → общий файл

Каждый смысловой вопрос задачи — отдельный файл в discussion/threads/. Файл discussion/00_all.md собирается скриптом, руками его не правят. CI проверяет, что сборка не устарела.

    Компромисс: презентации
    Обязательная презентация для нетривиальных задач удобна для приёмки, но добавляет работу к каждой такой задаче и блокирует ready-for-human, пока её нет. Если окажется тяжело, порог «нетривиальности» можно поднять.
