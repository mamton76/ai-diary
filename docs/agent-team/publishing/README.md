# Публикация презентаций задач (adapter, не источник истины)

**Назначение:** дать Product Owner прямую HTTPS-ссылку «открыть презентацию» из PR и задачи, не скачивая HTML. Канонические материалы остаются в `tasks/.../presentation/`.

## Что подготовлено

- Публикация **только явно разрешённых задач** из [public-previews.json](public-previews.json). В первом запуске разрешена TASK-0001 — синтетический HTML-обзор протокола.
- `python3 scripts/agent-team/build_preview_site.py` собирает переносимый статический сайт в `dist/agent-team-previews/` (главная страница и отдельные страницы `/TASK-NNNN/index.html`). Это не изменение исходных презентаций.
- CI проверяет, что сборка работает; публикация внешнего URL зависит от отдельно подключённого хостинга.
- Перед добавлением нового TASK-ID в allowlist агент проверяет отсутствие реального diary data, токенов, аккаунтов и иных приватных данных и получает **явное согласие Product Owner на публичную публикацию**. Не публиковать данные только потому, что они находятся в публичном репозитории.
- Если нужна приватная презентация, **не добавлять её в public-previews.json**. Нужен отдельный хостинг с авторизацией.

## Cloudflare Pages — одноразовое подключение владельцем

Рекомендуемый adapter для автоматического preview PR: [Cloudflare Pages Git integration](https://developers.cloudflare.com/pages/get-started/git-integration/). Подключение требует внешней авторизации; агент не может создавать проект в чужом аккаунте без подключения и разрешений.

1. Открыть Cloudflare Dashboard → **Workers & Pages** → **Create** → **Pages** → **Connect to Git**.
2. Подключить GitHub и дать доступ **только** репозиторию `mamton76/ai-diary`.
3. Выбрать репозиторий, **production branch: `master`**.
4. **Root directory:** корень репозитория; **Build command:** `python3 scripts/agent-team/build_preview_site.py`; **Build output directory:** `dist/agent-team-previews`.
5. Разрешить preview deployments для веток PR. После подключения сделать push в открытую ветку PR, если первый preview не появился автоматически.
6. Дождаться успешной сборки Cloudflare и взять **настоящий** URL из PR checks/Cloudflare; проверить в браузере путь `/TASK-0001/index.html`.
7. Только после проверки записать URL в `task.md`, `result.md` и PR. Не использовать предполагаемые адреса вида `some-project.pages.dev` до создания проекта.

При смене GitHub или Cloudflare экспорт можно развернуть на любом другом статическом хостинге без изменения канонических задач.

**Важно:** Cloudflare Pages preview URL, как правило, публичный, несмотря на название «preview». Использовать только отдельные явно одобренные демонстрационные презентации. Для приватных отчётов необходим доступ по аутентификации.
