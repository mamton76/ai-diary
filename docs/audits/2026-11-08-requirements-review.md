## 0. Итог в пяти пунктах

1. **Главная системная проблема — способ синхронизации решений.**
   - Решения из тредов дописываются блоками «Уточнение …» в конец inventory, product baseline и changelog Screens Spec (§26). Исходные пункты при этом не переписываются.
   - Блоки дублируются между файлами: 128 одинаковых строк в INV и PB.
   - Копии уже разошлись. Большинство противоречий ниже — следствие этого.
2. **Граница MVP описана по-разному в разных местах.**
   - Расходятся WEB-003, SEARCH-001, PB §12 и PB §22.
   - Объём подтверждённого для однопользовательского MVP большой: multi-user, leases, trusted executors, AI-бюджеты, MCP PoC, ранний Calendar Timeline.
3. **Нет требований к приватности и безопасности содержимого дневника.**
   - По `шифр|encrypt` во всём `docs/` 0 совпадений.
   - Не определены данные, уходящие LLM-провайдеру, удаление аккаунта, хранение refresh tokens.
   - DATA-010 (backup/export/restore) — заголовок без тела.
4. **Протокол Save не утверждён, а нужен уже первой пользовательской версии.**
   - FQ-03 в состоянии paused с зависшим claim с 18.10.
   - Обязательная проверка Drive (adapter spike) из 08 §2.2 не стоит в gates плана.
   - В плане нет шага, на котором legacy Abacus-скрипты перестают писать в хранилище.
5. **Живая система уже работает с реальными данными без атомарного commit** (аудит S2, Critical). Ни в архитектуре, ни в плане нет временных операционных ограничений на этот период.
