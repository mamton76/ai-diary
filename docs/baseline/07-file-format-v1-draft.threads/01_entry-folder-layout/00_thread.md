## Вопрос

Как раскладывать папки записей в Google Drive. Черновик 07 предлагает плоский `entries/<entryId>/`, чтобы папку не нужно было переносить при исправлении даты события.

## Варианты

1. Плоско по ID: `entries/<entryId>/` (черновик 07).
2. По дате создания: `entries/YYYY/MM/<entryId>/`.
3. По дате события с переносом при исправлении даты.
4. **Текущая раскладка живого дневника**: `entries/YYYY/MM/YYYY-MM-DD__entry_<id>/` по дате события на момент создания записи ([01_File_Storage_Structure.md §7](../../../../scripts/abacus/01_File_Storage_Structure.md)).

## Контекст

- В 07 FileRef хранит путь относительно корня хранилища и SHA-256; пути попадают в неизменяемые commit records и snapshots. Drive ссылается на файлы по ID, поэтому перенос папки в Drive дёшев, но пути в уже опубликованных записях после переноса устареют, и офлайн-копия или экспорт, читающие по путям, их не найдут.
- 07 §2 уже допускает чтение старой раскладки через resolver без автоматического переименования существующих папок.
- Существующий дневник использует вариант 4; сохранение этой раскладки избавляет от переименования папок при миграции.

пользователь — у нас сейчас такой вариант - это чем-т оплохо? может его и сохраним?

Claude — Ничем существенно не плох: папки читаются глазами, имя содержит дату и стабильный ID, и при миграции ничего не нужно переименовывать. Единственный вопрос — что делать, если дату события потом исправили (например, AI поставил «выведенную» дату по SQ-08, а пользователь её поправил). Перенос или переименование папки ломает пути в уже опубликованных commit records. Поэтому предлагаю сохранить вариант 4 с правилом: папка и её имя выбираются один раз при создании записи и **не переносятся** при изменении даты события. Дата в имени папки — подсказка для навигации, а не источник истины; актуальная дата — в Revision. Для записи без даты (Draft с `from = null`) берётся дата создания.

**Нужно от пользователя:** подтвердить вариант 4 с правилом «папка не переносится при изменении даты».
