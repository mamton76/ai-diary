## Вопрос

Если подключена интеграция с Google Calendar, должен ли web-клиент позволять запускать синхронизацию вручную, что именно она делает и где находится в интерфейсе?

## Варианты

1. **Кнопка «Синхронизировать сейчас» в S11 → Calendar.** Одна команда: импорт из Calendar Inbox, затем обновление Calendar Timeline. Рядом статус последнего запуска: когда, сколько импортировано, ошибки.
2. **Вариант 1 плюс видимость на Обзоре (S02).** Счётчик «ожидает импорта из календаря» и та же кнопка.
3. **Отдельный Inbox UI.** Список входящих событий календаря с импортом по одному или пачкой. Screens Spec §3 уже упоминает его «при необходимости».

## Контекст

**Что есть сейчас:**
- Screens Spec §3: «Интеграционный этап — Calendar inbox и Calendar timeline; при необходимости отдельный Inbox UI».
- План P2: «Начать с ручного запуска импорта небольшого набора, не блокируя сценарий на расписании sync».
- Кнопки запуска синхронизации на сайте нет ни в одной спецификации.
- Сейчас ручной запуск существует только в прототипе: Telegram-бот оператора с командами `/sync`, `/sync1`…`/sync3`, `/status` ([аудит](../../../audits/2026-11-08-abacus-diary-scripts.md)).

**Связанные решения:**
- [PQ-012](../47_PQ-012_mvp-stage-scope/00_thread.md): Calendar Inbox и Timeline — интеграционный этап, параллельно P2, до полноценного web UI.
- API-006A: команда ставится в durable очередь, UI различает «принята» и «выполнена».
- API-009: статусы фоновых задач в открытом web UI — через SSE.
- AUTH-008: при отключении Calendar импорт и Timeline останавливаются.

Claude — Идея закрывает реальный пробел: ручной запуск сейчас есть только в Telegram-боте прототипа, который аудит предлагает не путать с продуктом.

**Рекомендую вариант 1.**
- Это минимальный полезный объём: та же команда, что и плановая синхронизация, поставленная через общую очередь (API-006A). Статус приходит по SSE (API-009), так что новой механики почти нет.
- «Синхронизировать сейчас» не отменяет синхронизацию по расписанию, а дополняет её.
- Повторное нажатие во время уже идущей синхронизации не запускает вторую, а показывает текущую.

**Этап:** интеграционный, но кнопка появляется, только когда есть web, то есть не раньше E0. Предлагаю «интеграционный этап, web-кнопка — с первой web-версией после подключения Calendar».

Вариант 2 удобен, но требует счётчика «ожидает импорта», а значит регулярного опроса календаря. Вариант 3 — полноценный экран, его стоит делать, только если понадобится разбирать входящие события вручную.

**Нужно от пользователя:** выбрать вариант 1, 2 или 3 (или свой).

**Решение:** [принято] (2026-11-08) Вариант 2. Кнопка «Синхронизировать сейчас» есть в S11 → Calendar и на Обзоре (S02). Она ставит в общую очередь (API-006A) ту же команду, что и синхронизация по расписанию: импорт из Calendar Inbox, затем обновление Calendar Timeline. Расписание сохраняется. Повторное нажатие во время идущей синхронизации не запускает вторую, а показывает текущую; статус приходит по SSE (API-009). Рядом статус последнего запуска: когда, сколько импортировано, ошибки. Обзор показывает счётчик «ожидает импорта из календаря». Он вычисляется только при загрузке страницы (и после завершения запущенной синхронизации), без постоянного опроса календаря; может устаревать до перезагрузки. Без подключённого Calendar кнопка и счётчик скрыты. Этап: интеграционный; в web появляется с первой web-версией после подключения Calendar.
