## Вопрос

Source: «Для workflows, которые меняют metadata, желательно использовать schema validation. Нужно определить: JSON schema/Pydantic/Kotlin model; retry/repair; invalid output handling; user review».

## Варианты

Единственный пользовательский выбор — что делать, если ответ модели не прошёл проверку:

1. **Одна автоматическая попытка исправления** (модели отправляются ошибки проверки), затем видимая ошибка.
2. **Без автоматических попыток** — сразу видимая ошибка; повтор только вручную.
3. **До N попыток** (например, 3).

## Контекст

- AI-030 / [AQ-AI-002](../32_AQ-AI-002_workflow-definition/00_thread.md): output schema и декларативные правила проверки — часть versioned workflow definition; сложные проверки — отдельные trusted executors.
- [AQ-AI-001](../31_AQ-AI-001_provider-adapter/00_thread.md): adapter поддерживает structured outputs, capabilities моделей объявляются явно.

- FQ-06/SQ-04: AI-ошибка, требующая действия пользователя, попадает в Needs attention.
- Первый потребитель — извлечение данных из записи для минимального дайджеста (AI-037).

Claude — Предлагаю технический контракт:

1. **Схема** — JSON Schema как источник истины в workflow definition; Kotlin-типы генерируются из неё. Если модель поддерживает structured outputs, схема передаётся провайдеру; проверка на нашей стороне выполняется всегда.
2. **Два уровня проверки:** структурная (весь ответ по схеме) и смысловая по элементам (дата разбирается, тег существует, ссылка на запись реальна).
3. **Невалидная структура** — ответ целиком отклоняется. **Невалидные элементы** — отбрасываются по одному с записью причины в run record; валидные элементы принимаются.
4. **Как результат попадает в дневник** — по уже принятой политике workflow (PQ-005): безопасное применяется, остальное идёт в proposal и review. Проверка не заменяет review.
5. **Итоговая ошибка** — run получает статус «Не удалось разобрать ответ AI», ошибка видна в деталях запуска и попадает в Needs attention, если требует действия.

Рекомендую **вариант 1**: одна попытка исправления обычно чинит формат, стоит один дополнительный вызов и учитывается в бюджете; больше попыток быстро становятся дорогими.
