## Вопрос

Какие возможности форматирования нужны в первом редакторе Entry? Продуктовый выбор UX предшествует выбору библиотеки и физической сериализации.

## Варианты

1. Простое форматирование кнопками: жирный, курсив, списки и ссылки, без обязательного ручного ввода Markdown.
2. Обычный текст с абзацами/переносами без панели форматирования; форматирование отложено.

## Контекст

- AQ-WEB-003 / UI-Q04 прямо оставляют выбор editor semantics открытым; конкретная библиотека не обязательна.
- Source предпочитает durable human-readable representation, но UX не обязан показывать сырой Markdown.
- PQ-011 resolved по EntryPanel/History; text-diff style, ratios и другие визуальные детали отнесены к реализации. PQ-011 не выбирает форматирование редактора.
- Inline Asset между абзацами остаётся future; простой toolbar не означает выбор block editor или обязательность embedded media.
- Autosave/Save/Revision, tag mentions и proposal review не меняются автоматически от выбора форматирования.
- Выбор serialization/schema и совместимость текстового diff/mentions требуют дальнейшей технической проработки; не спрашиваем пользователя о библиотеке.
- При проверке текущих source/index/sibling-каталога canonical AQ-WEB-003 не найден; UI-Q04 ссылается сюда.

## Обсуждение

Codex — (2026-10-19) Следующая открытая развилка — первый редактор Entry. Предлагаю базовое форматирование кнопками: жирный, курсив, списки, ссылки; пользователь не обязан писать Markdown вручную. Альтернатива — только обычный текст с абзацами. Сейчас выбираем пользовательские возможности; библиотека и переносимая сериализация не утверждаются этой рекомендацией.
