## Вопрос

Для кого строится AI Diary: для самого пользователя, для семьи или для рынка? Какой минимальный цикл должен давать ценность, ради которой дневник вообще ведут?

## Варианты

1. **Личный инструмент.** Пользователь — автор проекта. Дневник служит слоем данных для ZoomAlboom.
2. **Продукт для рынка через вертикаль.** Детский дневник как первая ниша (направление из PRD и питча, апрель–май 2026).
3. **Личный инструмент сейчас, рынок позже.** Архитектура не закрывает путь к вертикалям, но продуктовые приоритеты задаются собственным использованием.

## Контекст

- [PRD §12](../../../prd.md) (весна 2026): «Baby & Early Years Diary» как самая сильная вертикаль для запуска; sharing как механизм удержания.
- Baseline (сентябрь–ноябрь 2026): web-first, файлы в Google Drive, «простота эксплуатации для персонального проекта». Вертикалей нет; sharing вне MVP ([PQ-007](../08_PQ-007_sharing-mvp/00_thread.md)).
- [Product baseline §4](../../03-product-baseline.md#4-границы-продукта): «AI Diary хранит события, содержание и смысл. ZoomAlboom хранит визуальную композицию и навигацию».
- По [§22.1](../../03-product-baseline.md#221-канонические-этапы-продукта) этапы E0–E3 посвящены чтению, поиску, редактору и тегам. AI-обработка начинается в E4, дайджестов и статистики в этапах нет.

Claude — Из этого следует:

- **Настоящий продукт — ZoomAlboom.** Главный критерий для фич дневника: делает ли фича материал для альбома лучше.
- **Единица для альбома — скорее эпизод (период + записи + медиа + описание), а не отдельная запись.** Выделение эпизодов стоит поднять в приоритетах.
- **Sharing остаётся вне AI Diary.** Делиться будут альбомами ZoomAlboom. Это согласуется с [PQ-007](../08_PQ-007_sharing-mvp/00_thread.md).
- **Для одного пользователя часть UI-строгости можно упростить.** Модель данных (raw, revisions, provenance) остаётся.

Предлагаемый главный цикл:

```text
захват (свободный текст/голос/фото + ответы на вопросы, PQ-015)
  → AI раскладывает запись по датам, людям, местам и трекерам
  → регулярный дайджест по почте со ссылкой в веб-клиент (PQ-016)
  → по событию: предложение собрать эпизод/альбом
  → (позже) передача в ZoomAlboom (FQ-ZOOMALBOOM-001)
```

Последствие для этапов: дайджест требует AI-обработки, которая сейчас стоит в E4. Если цикл принят, нужно решить, поднимается ли минимальная AI-обработка (извлечение полей + дайджест) раньше E4 или дайджест становится целью E4.

**Нужно от пользователя:** подтвердить формулировку «в первую очередь для себя, как подготовка к ZoomAlboom» и главный цикл выше. Если цикл принят — сказать, хочется ли получить дайджест раньше полноценного редактора (E2–E3) или после.

Claude — Принято:
- формулировка «в первую очередь для себя, как подготовка к ZoomAlboom» и главный цикл;
- дайджест и связанная AI-обработка остаются в E4. По словам пользователя, E4 начинается «после реализации первых этапов в каком-то объёме», то есть не обязательно после их полного завершения.

Вторая цель — портфолио — новая и имеет последствия: реальный дневник показывать нельзя, значит нужны демо-данные или демо-режим; важна видимость архитектуры и кода. Чтобы не решать это мимоходом, вынес её в отдельный вопрос [PQ-018](../56_PQ-018_portfolio-goal/00_thread.md).

**Решение:** [принято] (2026-11-08) AI Diary строится в первую очередь для себя, как подготовка материала для ZoomAlboom. Вторая цель — показать проект в портфолио пользователя; её последствия обсуждаются в [PQ-018](../56_PQ-018_portfolio-goal/00_thread.md). Главный ценностный цикл: захват (свободный текст, голос, фото и ответы на вопросы, PQ-015) → AI раскладывает запись по датам, людям, местам и трекерам → регулярный дайджест на почту со ссылкой в веб-клиент (PQ-016) → по событию предложение собрать эпизод или альбом → позже передача в ZoomAlboom (FQ-ZOOMALBOOM-001). Sharing — через альбомы ZoomAlboom, не внутри AI Diary. Дайджест, статистика динамики и предложение эпизода относятся к E4. E4 начинается после того, как первые этапы реализованы в достаточном объёме, не обязательно полностью. Рыночная вертикаль из PRD §12 не является текущим направлением.
