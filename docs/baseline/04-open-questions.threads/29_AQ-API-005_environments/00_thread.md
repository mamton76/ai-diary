## Вопрос

Нужны ли отдельные local/dev, staging, production environments уже в первой версии?

## Варианты

1. Полноценные dev/staging/prod.
2. Локальная разработка и отдельно постоянно развёрнутый production.
3. Одно рабочее deployed окружение, без поддерживаемых staging/test deployments; локальный запуск по необходимости.

## Контекст

Ранний личный прототип с приоритетом минимальных затрат и операционной сложности. Cloud Run ecosystem уже выбран как production runtime, но это не означает обязательность нескольких environments.

## Обсуждение

пользователь — «зачем нам разыне окружения? мне кажестя у нас пока оно одно не паримся»

ChatGPT — Согласен: пока нет необходимости оплачивать и обслуживать изолированные постоянно развёрнутые среды. Локальный запуск backend для разработки допустим, не превращая его в самостоятельное поддерживаемое окружение. Для опасных тестов нужны тестовые данные или backup, чтобы не уничтожать реальные записи.

**Решение:** [принято] (2026-10-18) Для текущего прототипа одно рабочее deployed окружение; не создавать отдельные staging/test deployments или независимые production-like environments. Локальные запуски допустимы по необходимости. Дополнительные окружения вводить только при конкретной потребности. Не проводить разрушительные эксперименты на единственной копии реальных diary data.
