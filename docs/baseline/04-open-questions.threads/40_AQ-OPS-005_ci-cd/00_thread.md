## Вопрос

Какие проверки запускать на PR, как выкладывать backend/web, нужен ли manual approval, где хранить секреты и как делать rollback?

## Обсуждение

ChatGPT — Были предложены ручной, полуавтоматический и полностью автоматический варианты. Рекомендация: автоматические проверки PR в GitHub, но deployment в единственное рабочее окружение только по явному ручному запуску. Не выкладывать каждый merge автоматически.

пользователь — «полуавтоматическое»

ChatGPT — Выбор подтверждён. Для MVP GitHub Actions автоматически запускает применимые проверки web/backend при PR (например, build/tests/lint по мере наличия), а deployment web/backend запускается вручную после успешных проверок. Секреты не хранятся в repository; использовать GitHub/Google Cloud secret mechanisms и ограниченные права. Возможность вернуться к предыдущей рабочей версии нужна, конкретный механизм rollback определяется при настройке deploy. Детали набора тестов и настройки workflow уточняются при реализации, не требуют отдельного постоянно развёрнутого staging.

**Решение:** [принято] (2026-10-18) Полуавтоматический CI/CD: автоматические PR checks, только ручной запуск deployment в единственное рабочее окружение. Без авто-deploy по merge. Секреты вне Git; предусмотреть документированный rollback предыдущей версии. Конкретный состав checks и команды deploy — при реализации.
