## Вопрос

Контроль стоимости AI, hosting, storage, logs и network egress.

## Обсуждение

пользователь — «а какие есть еще варианты?»

ChatGPT — Варианты: статистика расходов; мягкие предупреждения по бюджету; лимит, блокирующий новые платные AI-запуски; оценка перед дорогим массовым запуском; отдельные бюджеты для workflow/model; ограничения параллельности. Возможна комбинация. Проверять бюджет при исполнении задачи из очереди, а не только при постановке. Провайдерские бюджеты и облачные уведомления имеют разную семантику, поэтому нельзя считать любое предупреждение жёстким ограничением.

**Нужно от пользователя:** для MVP достаточно мониторинга или включаем блокировку новых платных AI-запусков при достижении пользовательского бюджета?

пользователь — «да - дополнительно блокировать новые AI-запуски при достижении бюджета»

ChatGPT — Принято для LLM: пользовательский месячный бюджет с мониторингом расходов и предупреждениями, а при достижении бюджета — блокировка новых платных AI-вызовов, включая запуск новых задач из очереди. Уже исполняющиеся запросы не отменяются автоматически; точное предотвращение overspend при параллельных задачах потребует проверки/резервирования оценочной стоимости перед dispatch. Отдельный технический вопрос — как оценивать ещё не завершённые запросы и учитывать провайдерские расходы, поэтому абсолютный billing hard cap этим решением не гарантируется. Для hosting/storage/logs/egress нужны внешние cloud alerts и cost visibility, но политику их отдельного ограничивания пользователь пока не выбирал.

**Нужно от пользователя:** как поступать с новыми AI-задачами, уже ожидающими в очереди на момент исчерпания бюджета: оставлять в состоянии paused/waiting for budget или завершать с ошибкой, чтобы пользователь сам перезапустил?

пользователь — «мне нравится что одидают бюджета - но как-то надо бы пользователя предупредить что они есть - чтобы он их руками застопал чтобы они не выжрали следующий бюджет (кстати тоже бы это сделать настройкой - переводить и требовать ручного старта или просто автоматически возобновляться)»

ChatGPT — Принята модель «Ожидает бюджета» без удаления queued runs. Пользователь должен явно видеть количество таких задач, суммарный ожидаемый расход (если оценка доступна), получать уведомление о накопленных задачах и иметь возможность отменить их до нового бюджетного периода. В настройках доступны два поведения при пополнении/обновлении бюджета: автоматическое возобновление или ручное подтверждение запуска. Рекомендация для экономного default — ручное возобновление, чтобы очередь не потратила следующий бюджет без внимания пользователя; выбор default уточняется. Отображение «Ожидает бюджета» не обязано делать запись проблемной, но наличие заблокированной очереди должно быть заметно в общих уведомлениях/панели задач.

**Нужно от пользователя:** подтверждаем ли ручное возобновление как настройку по умолчанию, с возможностью переключиться на автоматическое?
