## Вопрос

Можно ли сохранить Entry без Title/Text, если к ней привязан хотя бы один готовый Asset?

## Варианты

1. Разрешить запись только с материалами: например фото, аудио или документ без текстового описания; Event date и готовность attachments по существующим правилам.
2. Требовать текст и для записи с материалами.

## Контекст

- S05 прямо оставляет допустимость asset-only Entry открытой.
- Title и tags уже необязательны; fallback title не записывается как настоящий title.
- CaptureItem допускает media без исходного текста, но это не утверждает автоматически validation ручного Save Entry.
- Save уже disabled до готовности всех оставленных attachments.
- Полностью пустая запись без материалов и текста — отдельный остаток; этот вопрос касается наличия хотя бы одного готового Asset.
- В текущих source/index и sibling-каталоге отдельного canonical thread по asset-only Save не найдено.

## Обсуждение

Codex — (2026-10-18) После permanent delete следующий продуктовый вопрос — Entry только с материалами. Рекомендую разрешить Save с фото/аудио/документом и Event date без обязательных Title/Text: пользователь не должен придумывать описание только ради сохранения материала. Название отображается по принятому fallback. Точный fallback и полностью пустая запись не выбираются этим вопросом. Это предложение, не принятое требование.

пользователь — (2026-10-18) «думаю да»

Codex — (2026-10-18) Принято сохранение Entry только с готовыми материалами без Title/Text. Обязательность Event date и готовность всех оставленных attachments/прочие Save guards сохраняются. Не требуется сначала генерировать AI-текст или придумывать описание; fallback title — только отображение. Это обычная Entry/Revision, не отдельная сущность. Допустимость полностью пустой записи не выбрана. Решение перенесено в Functional/Screens Specs, inventory/product baseline.

**Решение:** [принято] (2026-10-18) Entry разрешено сохранять без Title/Text при наличии хотя бы одного готового связанного Asset. Все остальные Event date/Save/attachment checks сохраняются. Первый Save создаёт первую Revision с материалами, без обязательного AI-текста и без записи fallback как реального title.
