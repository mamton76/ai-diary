## Вопрос

Разрешать ли manual Save полностью пустой Entry — без Title, Text и Asset links?

## Варианты

1. Не создавать committed Revision полностью пустой записи. Draft сохраняется по общим правилам; Save disabled с объяснением до появления заголовка, текста или материала.
2. Разрешить date-only/metadata-only Entry, даже без заголовка, текста и материалов.

## Контекст

- UI-Q14 разрешил asset-only Entry, но прямо оставил полностью пустую запись открытой.
- Event date имеет видимый default; сам по себе он не означает пользовательский ввод содержимого.
- Новая Entry уже имеет ID/Draft; нельзя терять внесённые metadata или автоматически удалять Draft из-за невалидности для Save.
- Предлагаемая проверка относится к итоговому содержимому manual Save; создание пустого Draft не запрещается.
- В первом варианте пробельные Title/Text не считаются содержимым; это validation, не изменение точного content equality при NO_CHANGE. Теги и Event date не заменяют заголовок/текст/материал.
- Общие Asset readiness/lease/base guards сохраняются.
- Существующего canonical thread по этому выбору в source/index/sibling-каталоге не найдено.
