## Вопрос

Разрешать ли manual Save полностью пустой Entry — без Title, Text и Asset links?

## Варианты

1. Не создавать committed Revision полностью пустой записи. Draft сохраняется по общим правилам; Save disabled с объяснением до появления заголовка, текста или материала.
2. Разрешить date-only/metadata-only Entry, даже без заголовка, текста и материалов.

## Контекст

- UI-Q14 разрешил asset-only Entry, но прямо оставил полностью пустую запись открытой.
- Event date имеет видимый default; сам по себе он не означает пользовательский ввод содержимого.
- Новая Entry уже имеет ID/Draft; нельзя терять внесённые metadata или автоматически удалять Draft из-за невалидности для Save.
- Предлагаемая проверка относится к итоговому содержимому manual Save; создание пустого Draft не запрещается.
- В первом варианте пробельные Title/Text не считаются содержимым; это validation, не изменение точного content equality при NO_CHANGE. Теги и Event date не заменяют заголовок/текст/материал.
- Общие Asset readiness/lease/base guards сохраняются.
- Существующего canonical thread по этому выбору в source/index/sibling-каталоге не найдено.

## Обсуждение

Codex — (2026-10-18) После разрешения asset-only Entry остаётся полностью пустая запись. Предлагаю сохранять её Draft по общим правилам, но не разрешать manual Save, пока нет заголовка, текста или материала; пояснение рядом с disabled Save. Альтернатива — разрешить самостоятельную запись-маркер только с датой/metadata. Это ещё не принятое требование.

пользователь — (2026-10-18) «ну ок»

Codex — (2026-10-18) Принят первый вариант: manual Save недоступен, пока итоговый snapshot не содержит заголовка, текста или готового материала. Дата/теги не заменяют содержимое; чистые пробелы тоже не заменяют его. Проверка не нормализует bytes сохраняемого текста, поэтому точное сравнение NO_CHANGE сохраняется. Draft/metadata не теряются и не удаляются автоматически; остальные Save guards действуют. Title-only и ранее принятая asset-only Entry допустимы. Решение перенесено в обе спецификации и inventory/product baseline.

**Решение:** [принято] (2026-10-18) Полностью пустая Entry остаётся Draft; manual Save disabled с пояснением до появления содержательного Title/Text или готового связанного Asset. Одних даты/тегов/служебных metadata и чистых пробелов недостаточно. Draft сохраняется по общим правилам без автоматического Discard; прочие Save guards и точное content equality не меняются.
