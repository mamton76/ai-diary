## Вопрос

Что именно удаляет Delete permanently для самой Entry: только Current либо также её raw, revisions, Draft и связанное содержимое AI?

## Варианты

1. Полное удаление содержимого Entry: Current, revisions, её raw и Draft, proposals и сохранённые текстовые input/output этой Entry в AI history. Оставить лишь минимальный технический след без текста для целостности общих связей/операций.
2. Удалить Current, сохранив старое содержимое в истории. Это требует явно объяснять, что удаление не является полным, и определять отдельную политику хранения текста.

## Контекст

- Entry Trash уже имеет Restore и Delete permanently, без автоматического таймера; soft delete сохраняет Entry/Draft/history.
- UI-Q07 / FQ-08 прямо оставляют последствия permanent delete для зависимых объектов открытыми; отдельного canonical thread по этому выбору при проверке каталога не найдено.
- Нельзя удалять общие Asset, определения routines, другие Entries или содержимое других участников общего batch как часть удаления одной Entry.
- Политика общих вложений уже различает unlink и явное soft delete; этот вопрос касается содержимого самой Entry.
- SQ-02 запрещает удаление external originals; не переоткрываем это решение.
- Сохраняемый minimal audit не должен включать удаляемый текст. Физический протокол, in-flight guards, индексы/копии и backup retention требуют отдельной технической проработки; этот продуктовый вопрос не обещает немедленное стирание резервных копий.

## Обсуждение

Codex — (2026-10-18) Следующий открытый вопрос — объём окончательного удаления Entry. Рекомендую удалять всё её содержимое: текущую запись, исходник, все revisions и Draft, предложения и сохранённые текстовые input/output AI по этой Entry. Оставлять лишь минимальный технический след без текста; общие объекты/чужое содержимое не удалять. Вложенные материалы следуют отдельной принятой политике. Это предложение, не принятое требование.

пользователь — (2026-10-18) «а мы прям удаляем-удаляем - не в архив склдаываем? у нас есть возможость отменить удаление?»

Codex — (2026-10-18) Уточнены три разных действия: Archive обратим; обычное Delete отправляет сохранённую Entry с Draft/history в Trash и допускает Restore; отдельное Delete permanently из Trash требует явного подтверждения, после него восстановления нет. Автоматического таймера нет. Вопрос касается только последней операции, решение на этом шаге ещё не принято.

пользователь — (2026-10-18) «а ну если финальный - да все - про ассеты спросить связанные если они тольок в этой записи»

Codex — (2026-10-18) Принято полное удаление содержимого Entry и отдельный вопрос про исключительно связанные Asset. Для них применяется уже принятая политика предложения soft delete в Asset Trash, с возможностью оставить в библиотеке; финальное удаление Asset не подразумевается согласием удалить Entry. Общие потребители проверяются по AST-08, включая archived/history/Draft/операции; свои revisions одной Entry не считаются отдельными потребителями. Внешние originals не удаляются. Минимальный технический след не содержит текста. Shared sources/общий batch не удаляются целиком за одну Entry; техническая очистка её копий, late-writes/rebuild guards и backup retention остаются в проработке, не объявлены реализованными. Продуктовое решение перенесено в обе спецификации и inventory/product baseline.

**Решение:** [принято] (2026-10-18) Отдельно подтверждённое Delete permanently из Entry Trash удаляет всё принадлежащее этой Entry содержимое: Current, raw, revisions, Draft/review draft, предложения и текстовую AI history, оставляя только минимальный технический след без содержимого. Undo/Restore после завершения нет; обычные Archive/Delete остаются обратимыми. Для Asset, у которого удаляемая Entry была единственным логическим потребителем, отдельно предложить soft delete в корзину материалов либо сохранение в библиотеке. При других потребителях сохранить Asset, убрать только связи этой Entry; внешние originals не удалять. Удаление одной Entry не удаляет чужое содержимое/общие определения или весь общий batch.
