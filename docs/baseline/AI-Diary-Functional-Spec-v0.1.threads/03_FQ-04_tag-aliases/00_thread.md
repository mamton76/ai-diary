## Вопрос

Коллизии aliases, удаление chip при сохранённом hashtag, формат suffix normalizer. Нужен предсказуемый tag lookup/normalization без потери текста.

Сначала обсуждаем один вопрос: может ли один alias относиться к нескольким самостоятельным canonical tags? Затем — поведение unlink/text и суффикс Save. Уникальность canonical names и точные правила нормализации строк не считаются выбранными этим обсуждением автоматически.

## Варианты

1. Разрешить совпадающий alias у нескольких tags. В ручном autocomplete показывать отдельные canonical candidates; пользователь выбирает конкретный tagId. Само совпадение alias не выбирает первый тег и не связывает со всеми кандидатами.
2. Требовать глобально уникальный alias в каталоге самостоятельных активных tags. Конфликтующее имя нельзя добавить как alias второго тега; пользователь должен выбрать другой alias либо осознанно выполнить merge.

## Контекст

Принято: связь хранится по tagId, chips — source of truth. Поиск идёт по canonical name и aliases, direct canonical matches выше alias-only. Выбор alias вставляет этот alias в текст, chip показывает canonical name. Raw hashtag сам по себе связь не создаёт. Rename добавляет old name в aliases, merge переносит aliases с дедупликацией и использует canonical redirect.

Последствия выбранной collision policy должны применяться и к Rename/Merge/Create/Restore; конкретные правила этих операций при коллизиях нужно уточнить после выбора. Здесь не объявляется дополнительное разрешение AI связывать ambiguous aliases: routine policy и confidence checks продолжают действовать.

FQ-03: пользовательское поведение Save/retry/read-only editor уже согласовано. Технический multi-file commit/recovery остаётся незакрытым исследовательским остатком, а не автоматически решённым вопросом; переход к FQ-04 не утверждает протокол.

Повторы aliases внутри одного canonical tag дедуплицируются. Merge redirect разрешается в survivor и не считается вторым самостоятельным владельцем alias.
