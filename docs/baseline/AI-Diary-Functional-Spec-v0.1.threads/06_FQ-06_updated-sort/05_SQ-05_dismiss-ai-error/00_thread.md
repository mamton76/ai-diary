## Вопрос

Разрешить ли пользователю явно убрать из Needs attention конкретную ошибку AI, если обработка больше не нужна и повторять её не хочется?

## Варианты

1. **Рекомендация:** да, действие «Убрать из внимания» снимает только эту причину ошибки. История неуспешного Run сохраняется; успех обработки не имитируется. Другие причины Entry остаются. Новая ошибка другого/нового запуска снова может потребовать внимания.
2. Нет: ошибка остаётся причиной внимания до успешного повторного выполнения или другого разрешения проблемы; простое подтверждение пользователем не снимает её.

## Контекст

- [SQ-04](../04_SQ-04_failed-ai-attention/00_thread.md) уже определяет очередь и число через актуальные причины, требующие пользователя. Фоновая работа сама по себе не считается.
- Пользователь может сознательно отказаться от необязательного AI enrichment этой Entry. Неуспешная обработка не должна помечаться успешной от снятия индикатора.
- Предлагаемое действие относится только к одной ошибке/причине; это не общий «Скрыть всё» для Entry, не отклонение остальных proposals и не разрешение конфликта.
- Предложение не удаляет Entry, content Revision или историю AI и не создаёт content Revision.
- Это не глобальное выключение routine, не запрет будущих запусков и не отмена уже выполняющегося job. Фоновая отмена и retry-policy имеют отдельный контракт.
- Новая попытка с новой неразрешённой ошибкой не наследует автоматически скрытие предыдущей.
- Точные IDs resolution records/audit, storage path и название/расположение кнопки — последующая техническая/UI-конкретизация, не выбранные заранее требования.

## Обсуждение

Codex — (2026-10-18) Предлагаю разрешить «Убрать из внимания» для конкретной ошибки AI, если пользователь больше не хочет выполнять эту обработку. Ошибка остаётся в истории, другие причины внимания сохраняются. Новая ошибка нового запуска снова видна по общим правилам. Это рекомендация, ещё не принятое правило.

пользователь — (2026-10-18) «оки»

Codex — (2026-10-18) Явное снятие конкретной причины ошибки разрешено. Решение перенесено в Functional/Screens Specs, inventory/product baseline. Проверка следующей темы показала: stale/conflict review уже согласован в PQ-005 и действующих спецификациях. Новый выбор поэтому касается открытого FQ-07 — судьбы непринятых частей после частичного Apply, а не повторного согласования блокировки stale proposal.

**Решение:** [принято] (2026-10-18) Пользователь может явно убрать из «Требует внимания» конкретную причину ошибки AI без успешного повторного запуска, если обработка больше не нужна. Снимается только эта причина; неуспешный Run и его история сохраняются и не помечаются успешными. Другие причины внимания Entry остаются; при отсутствии остальных причин Entry выходит из очереди и счётчика. Новая ошибка нового запуска может снова потребовать внимания и не наследует снятие прежней. Действие не удаляет Entry/историю, не создаёт content Revision, не выключает routine глобально и не отменяет выполняющийся job.
