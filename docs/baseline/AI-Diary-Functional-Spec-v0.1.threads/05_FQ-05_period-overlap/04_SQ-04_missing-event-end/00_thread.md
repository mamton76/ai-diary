## Вопрос

Что означает отсутствие To у самой записи для Calendar и period filter? Это не отсутствие верхней границы у пользовательского фильтра.

## Варианты

1. **Рекомендация:** одиночное событие на заданную From дату/время; отсутствие To не делает его длящимся до текущего дня или бесконечно. Если указана только дата — для дневного Calendar запись относится к этой дате; точное время не придумывается. Если указано время — опорой служит этот момент, без выдуманной длительности.
2. Считать отсутствие To незавершённым, продолжающимся событием и включать последующие дни до явно указанного окончания. Это добавляет смысл ongoing к отсутствию поля.

## Контекст

- From date обязательна для ручного Save; From time и To optional.
- Date-only не заменяется на 00:00, данные сохраняют точность.
- Принят period overlap для интервалов с указанными границами.
- День Calendar и связанный дневной фильтр используют местные даты события, не пересчёт в пользовательскую зону.
- Optional To в query filter имеет другой смысл: только From = нижняя граница фильтра. Текущий выбор не меняет это правило.
- Выбор одиночного события не требует физически записывать To=From и не утверждает точные mixed-precision/граничные comparisons.
- Отдельный явный ongoing flag не предлагается как уже существующая функция; при необходимости он требует самостоятельного решения.

## Обсуждение

Например, «18 октября» видна на 18 октября и не продолжается автоматически 19-го, 20-го и далее. Для интервальной записи пользователь указывает окончание. Это рекомендация, ещё не принятое правило.

Если указана только дата, дневной Calendar и связанный date filter относят запись к этой местной дате без выдуманного времени суток.
