## Вопрос

Что делать, если у даты события нет никакого основания (фото без EXIF, импорт или голосовая заметка без упоминания даты)? После [SQ-07](../07_SQ-07_time-precision-serialization/00_thread.md) минимальная точность для Save — день, пометка `approximate` требует основания, а AI не может выдумывать дату (ENTRY-008, Functional Spec §5).

## Варианты

1. Запись остаётся в Draft без даты и попадает в Needs attention.
2. Ставится дата получения с новой пометкой `inferred` («выведено»).
3. Другое.

## Контекст

- [SQ-07](../07_SQ-07_time-precision-serialization/00_thread.md): `uncertainties: [{field, kind, evidence}]`, для `approximate` evidence обязателен; `inferred` в SQ-07 не выбирался и из schema был убран.
- [PQ-005](../../../04-open-questions.threads/05_PQ-005_ai-automation-policy/00_thread.md) / AI-11: первая normalized Entry может создаваться автоматически из сохранённого raw с явной uncertainty.
- ENTRY-008: неопределённость хранится явно, а не как выдуманный факт.

Claude — Принято, вариант 2. Техническая конкретизация без нового выбора: дата получения — местная дата приёма исходного материала (CaptureItem) в поясе из настроек пользователя, без времени суток; пояс записи — тот же. `evidence` для `inferred` обязателен и называет источник даты (например, «дата получения голосовой заметки»). Если пользователь сам задаёт или подтверждает дату, пометка снимается, потому что дата становится его утверждением. Если основание есть (например, «прошлым летом»), применяется `approximate` из SQ-07, а не `inferred`. Решение перенесено в source-документы.

**Решение:** [принято] (2026-11-15) Если у даты события нет основания, ставится местная дата получения исходного материала в поясе из настроек пользователя, без времени суток, с пометкой `uncertainties: [{field: "from", kind: "inferred", evidence: <источник даты>}]` («выведено»); evidence обязателен. Если основание есть, используется `approximate` (SQ-07). Когда пользователь сам задаёт или подтверждает дату, пометка снимается.
