## Вопрос

Остаток FQ-05 после SQ-01…SQ-06: как хранить EventTimeRange, как сравнивать точки разной точности и в разных часовых поясах (включая DST), и что делать, если дата события неизвестна или приблизительна. Это нужно уже для формата файлов E0.

## Варианты

Для единственного пользовательского выбора — неизвестная или приблизительная дата:

1. **Минимум — день.** Save требует дату события; приблизительность хранится пометкой «примерно» с исходным основанием. Месяц или год без дня — Later.
2. **Точность до месяца или года сразу** («лето 2019», «2015»).
3. **Разрешить Save без даты** (запись «без даты»).

## Контекст

- Уже решено: overlap при фильтрации; «сегодня» по поясу из настроек (SQ-01); показ в местном времени события (SQ-02); календарь по местной дате события (SQ-03); отсутствующий To — одиночное событие (SQ-04); последний день date-only интервала включён (SQ-05); date-only запись попадает в фильтр по часам как возможное совпадение (SQ-06).
- [07-file-format §4](../../../07-file-format-v1-draft.md): codec `{"from": {"date", "time"}, "to", "timeZone", "uncertainties"}`; Draft может иметь from=null; ручной Save требует from.date.
- Ревью 2026-11-08 (M5): «обязательный Event date» конфликтует с ENTRY-008 «явная неопределённость»; (M13): `uncertainties` — массив строк без evidence.

## Обсуждение

Claude — Предлагаю техническую часть (не требует выбора, только подтверждения):

1. **Хранение:** точка = `date` (YYYY-MM-DD) + `time` (HH:MM или null); один IANA `timeZone` на запись; `to` может отсутствовать. Так уже в 07.
2. **Смешанная точность:** у одной записи from и to могут иметь разную точность. Для сравнения каждая точка превращается в момент времени в часовом поясе записи: date-only from — начало дня, date-only to — конец дня (SQ-05), точка со временем — ровно этот момент.
3. **Разные пояса:** интервал записи считается в её поясе, фильтр — в поясе из настроек; пересечение сравнивается по абсолютному времени. Календарь по-прежнему группирует по местной дате события (SQ-03).
4. **DST:** несуществующее местное время (переход вперёд) сдвигается на первый существующий момент, неоднозначное (переход назад) берётся более раннее; сохранённые местные значения не меняются.
5. **Неопределённость:** `uncertainties` становится списком объектов `{field, kind, evidence}` (например, `{field: "from", kind: "approximate", evidence: "…"}`), а не строк.

Рекомендую **вариант 1** для неизвестной даты: он закрывает ENTRY-008 пометкой «примерно» без новых видов точности; AI при нормализации ставит наиболее вероятный день и пометку, пользователь правит. Вариант 2 полезен для воспоминаний, но усложняет календарь, фильтры и статистику — лучше Later.
