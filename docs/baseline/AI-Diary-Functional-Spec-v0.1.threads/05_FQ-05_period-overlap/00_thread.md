## Вопрос

Первый подпункт FQ-05: как учитывать запись с заданными From и To при фильтрации по периоду? Остальные FQ-05 — точные границы, mixed precision, timezone, uncertainty и serialization — пока отдельно не решены.

Пример без спорной граничной точки: запись «Поездка» с 1 по 10 июля, выбран период 5–7 июля.

## Варианты

1. **Рекомендация:** включать запись, если хотя бы часть её интервала пересекается с выбранным периодом. Поездка 1–10 июля показывается при фильтре 5–7 июля.
2. Отбирать по началу события: поездка не попадёт в 5–7 июля, потому что начинается 1 июля.
3. Включать только записи, целиком находящиеся внутри выбранного периода: поездка 1–10 июля не попадёт в 5–7 июля.

## Контекст

- Запись имеет EventTimeRange from/optional to/timeZone.
- Фильтр From/To — отдельный объект, может быть односторонним.
- Generic filter используется Browser; выбор Calendar переводится в date filter.
- Счётчик и список по его клику должны иметь одну область; запись не дублируется по числу дней.
- Draft-state используется там, где это уже принято; текущий выбор не меняет lifecycle scope.
- Конкретные <= / < на границах, date-only/day intervals, DST, отсутствующий To и uncertain dates этим примером не выбираются автоматически.
- Наличие общего FilterBuilder не означает требования добавить все три режима в MVP: сначала выбирается default semantics.

**Решение:** [принято] (2026-10-18) Фильтр по периоду включает интервальную Entry, если хотя бы часть её EventTimeRange пересекается с выбранным периодом; не требуется попадание начала или всего интервала внутрь фильтра. Например, поездка 1–10 июля видна при фильтре 5–7 июля. Одна Entry показывается один раз, независимо от количества пересекающихся дней. Это общее правило date filter; выбор календаря и связанные выборки используют ту же semantics при неизменном lifecycle scope.
