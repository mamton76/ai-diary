## Вопрос

Разрешать ли после пользовательской отмены обычный повтор для отменённых/необработанных Entries без успешного результата, при сохранении already-processed skip для успешно завершённой части той же routineVersion/input Revision?

Пример: из выбранных 20 Entries успешно обработаны 7, остальные отменены без результата. Пользователь позже сам запускает повтор для этого набора при неизменных routine/input versions.

## Варианты

1. **Рекомендация:** обычный повтор может обработать оставшиеся 13; отмена без результата сама по себе не означает already processed. Готовые 7 пропускаются по прежним правилам; сознательный повтор готовой части — отдельный Force rerun.
2. Отменённые Runs тоже блокируют обычный повтор: для оставшейся части требуется Force rerun, хотя успешного результата ещё нет.

## Контекст

- [SQ-03](../03_SQ-03_batch-cancel-results/00_thread.md) уже сохраняет готовую часть при отмене; автоматического отката нет.
- [SQ-02](../02_SQ-02_failed-run-retry/00_thread.md) разрешает обычный повтор достоверного failure без результата; cancelled там явно оставался отдельным случаем.
- Вопрос предполагает отсутствие успешного результата у отменённой/необработанной части. Partial success одного Run или неизвестный исход сначала требуют reconciliation; их нельзя слепо объявить отменёнными без результата.
- Сначала должно быть подтверждено прекращение прежней queued/running работы; новый запуск не создаёт параллельный дубль.
- Это пользовательский повтор после отмены, не автоматическое возобновление отменённого batch.
- Обычные eligibility/Draft/lease/input checks сохраняются; если версия или scope изменились, применяются общие правила соответствующего нового запуска.
- Текущий вопрос не выбирает UI snapshot-selection vs повтор текущего filter, storage IDs попыток, автоматические retry budget или scheduler behavior.
- Отклонённое пользователем предложение успешно выполненного Run не приравнивается к отмене Run без результата и сохраняет already-processed правило.
