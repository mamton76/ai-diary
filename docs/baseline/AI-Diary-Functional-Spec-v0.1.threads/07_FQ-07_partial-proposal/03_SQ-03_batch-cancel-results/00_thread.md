## Вопрос

Пользователь отменяет пакетную AI-обработку, когда часть Entries уже успешно обработана. Отмена только останавливает оставшуюся работу или также должна автоматически отменять уже полученные результаты?

## Варианты

1. **Рекомендация:** остановить оставшуюся работу, сохранив уже успешно опубликованные результаты: proposals и разрешённые policy committed изменения. Их статус/история остаются доступны. Отмена не является массовым Undo/Reject.
2. Дополнительно откатить/отклонить все готовые результаты этого batch. Это требует отдельной безопасной модели rollback при возможных пользовательских изменениях после каждого результата.

## Контекст

- AI jobs могут отменяться; закрытие браузера само по себе их не отменяет.
- Уже принято STO-04: отменённый/потерявший lease job не получает право commit после отмены, даже если внешний AI ответ пришёл позже. Это правило не пересматривается.
- Уже созданный pending proposal не является committed Entry content. Сохранение его после отмены batch не равно Apply.
- Первая normalization/existing tags могут auto-apply только по ранее принятой routine policy; отмена batch не расширяет её.
- [AQ-API-004](../../../04-open-questions.threads/28_AQ-API-004_background-processing/00_thread.md) задаёт queue-first и durable jobs; сохранность готовых результатов при пользовательской отмене там не выбиралась отдельно.
- Очередь прекращает запуск ещё не начатой работы; для выполняющейся работы нужна отмена по текущему job/mutation contract. Точные race/commit linearization и provider cancellation mechanics — техническая конкретизация.
- История batch должна различать успешно завершённую часть и неисполненную/отменённую; конкретный storage enum не выбирается этим вопросом.
- Повторная eligibility отменённой части и частично успешного Run — отдельный аспект, не автоматическое следствие решения о rollback.

## Обсуждение

Codex — (2026-10-18) Предлагаю при отмене batch остановить оставшуюся обработку, а уже полученные и опубликованные результаты оставить. Например, готовы предложения для 7 из 20 записей — семь сохраняются, оставшаяся работа останавливается. Отмена не пытается массово откатить ранее разрешённые изменения. Это рекомендация, ещё не принятое правило.

пользователь — (2026-10-18) «мне кажется да»

Codex — (2026-10-18) Принят вариант сохранения готовых результатов; отмена останавливает оставшуюся работу без массового rollback/Reject. Исходный cancellation/late commit guard сохраняется. Решение перенесено в обе спецификации, inventory/product baseline. Сразу открыт [SQ-04 — обычный повтор отменённой части](../04_SQ-04_interrupted-batch-retry/00_thread.md); eligibility cancelled без результата не приписывается ранее согласованному failed без результата.

**Решение:** [принято] (2026-10-18) При отмене пакетной AI-обработки сохраняются уже успешно опубликованные результаты: pending proposals и разрешённые routine policy committed изменения. Оставшаяся работа останавливается по общему cancellation contract; отмена не выполняет массовый Undo/Reject уже готовых результатов. Pending proposal не становится применённым от сохранения после отмены. Отменённый job не получает право позднего commit; история batch различает завершённую и отменённую/неисполненную части.
