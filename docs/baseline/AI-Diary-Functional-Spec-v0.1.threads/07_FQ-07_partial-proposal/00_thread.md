## Вопрос

Пользователь принял часть complex proposal через редактируемый Result и подтвердил Apply. Что происходит с непринятыми изменениями этого proposal: разбор завершён целиком или оставшиеся части продолжают ждать решения?

Пример: AI предложил переписать абзац и добавить три тега. Пользователь сохранил свой абзац, принял только теги и подтвердил итоговый Result.

## Варианты

1. **Рекомендация:** завершить разбор proposal целиком с понятным исходом «применено с изменениями». Сохраняются исходный AI Proposal и подтверждённый Result/созданная Revision; оставленные пользователем за пределами Result изменения не остаются pending и автоматически не превращаются в новые proposals. Сам этот proposal больше не является причиной Needs attention.
2. Оставить непринятые части pending для последующего разбора. Потребуются точная per-part модель, актуализация base после созданной Revision и отдельное отображение оставшегося объёма.

## Контекст

- [PQ-005 — согласованная AI policy и review](../../04-open-questions.threads/05_PQ-005_ai-automation-policy/00_thread.md) уже разрешает complex proposals и частичное принятие через Result. Это не новый выбор, разрешать ли partial review.
- Detailed review: Base / editable Result / Proposal; подтверждение создаёт одну content Revision. Quick Apply/Reject относятся к proposal целиком.
- Stale/conflicted proposal не имеет быстрого Apply; подробный review учитывает Current, независимые изменения могут merge в Result, конфликты разрешаются явно. Эта существующая policy здесь не пересматривается.
- Экранная спецификация §12.3 явно оставляет исход непринятых частей открытым; нового canonical треда на этот выбор до открытия узла не было.
- Needs attention учитывает незавершённые причины; закрытие одного proposal не скрывает другие proposals, ошибки или conflicts Entry.
- Вариант 1 не помечает весь исходный AI output принятым дословно: подтверждён именно Result. Различие Proposal/Result и provenance сохраняются в AI activity.
- Точный storage enum/shape resolution и mapping отличий по фрагментам — технический проект. Пользовательский исход не требует заранее выбирать схему.
- Вариант 1 не запускает AI автоматически заново и не изменяет already-processed/Force rerun policy.

## Обсуждение

Codex — (2026-10-18) Предлагаю после подтверждения частично принятого Result завершать разбор всего proposal как «применено с изменениями». Например, приняты теги, предложенный абзац оставлен за пределами Result — абзац не остаётся висеть новым незавершённым решением. Исходное предложение и реальный результат доступны в истории AI; создаётся одна Revision. Это рекомендация, ещё не принятое правило.

пользователь — (2026-10-18) «я так понимаю что при показе предложения - мы видм же условно гит мерж - 3 панели - исходник, реузльтат (с подсветой изменений), предложения (с подсветкой). и да - если что-то откллоянем из предложения принято частично нормлаьный статус»

Codex — (2026-10-18) Подтверждён трёхпанельный review Base / editable Result / read-only Proposal. Подсветка изменений в Result и Proposal относительно Base перенесена в source; Current при изменении учитывается прежним conflict/review flow. Пользовательское название исхода — «Принято частично» вместо ранее предложенного «применено с изменениями». После подтверждения разбор proposal завершается целиком; исходный AI результат и реальный Result сохраняются, непринятые части не создают новый pending. Решение перенесено в обе спецификации и inventory/product baseline. Следующий отдельный выбор — [сохранение прогресса незавершённого review](01_SQ-01_review-draft-resume/00_thread.md).

Codex — (2026-10-18) SQ-01 завершён: незавершённый review Result автосохраняется и восстанавливается, как Draft Entry; до Apply Current/History не меняются. Сразу открыт SQ-02 — ordinary retry vs already processed после failed Run без успешного результата. Технический retry/unknown-outcome protocol не объявляется выбранным.

Codex — (2026-10-18) SQ-02 завершён: достоверный failed Run без результата допускает обычный повтор, без already-processed block только по факту ошибки. Платные автоматические retries сохраняют ранее принятую пользовательскую policy AQ-OPS-002. Сразу открыт SQ-03 — сохранять ли уже готовые результаты при отмене batch; cancellation commit guard из STO-04 сохраняется.

Codex — (2026-10-18) SQ-03 завершён: отмена batch сохраняет готовые результаты и останавливает оставшуюся работу без массового отката. Сразу открыт SQ-04 — eligibility отменённой/необработанной части для обычного пользовательского повтора; успешно завершённая часть сохраняет уже принятые правила already processed.

Codex — (2026-10-18) SQ-04 завершён на уровне поведения: обычное продолжение обрабатывает оставшуюся часть; явный Force rerun повторяет выбранный набор, включая готовую часть. Короткие UI-названия дорабатываются по просьбе пользователя; предложены «Продолжить» / «Повторить всё». Это редакционное уточнение, не снятие принятого решения.

Codex — (2026-10-18) По запросу «что дальше» открыт отдельный SQ-05 — источник набора Entries для продолжения/полного повтора конкретного batch. SQ-04 намеренно не выбирал исходный snapshot IDs vs текущий filter. Рекомендация исходного списка пока не принята; короткие UI-названия по-прежнему остаются редакционным вариантом.

**Решение:** [принято] (2026-10-18) Подробный review использует три панели: исходник Base — сохранённое состояние, на котором работал AI, только чтение; Result — редактируемый будущий итог; Proposal — исходное предложение AI, только чтение. В Result и Proposal подсвечиваются изменения относительно Base. Если пользователь принимает только часть предложения и подтверждает итоговый Result, proposal получает понятный статус «Принято частично» и закрывается целиком как разобранный. Создаётся одна committed Revision с подтверждённым Result, без дополнительного Save. Исходный Proposal и итоговый Result/Revision сохраняются в AI history; непринятые части не остаются pending и автоматически не превращаются в новые proposals. Причина внимания этого proposal снимается, остальные причины Entry сохраняются.
