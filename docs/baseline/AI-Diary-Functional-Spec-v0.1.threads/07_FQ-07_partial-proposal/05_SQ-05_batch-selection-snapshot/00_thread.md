## Вопрос

Для продолжения или полного повтора конкретного batch использовать исходный список Entry IDs этого запуска либо заново вычислять выборку по изменившимся фильтрам/данным?

Пример: на старте выбраны 20 Entries по тегу. Позже под тот же filter попали ещё две новые Entry. Пользователь возвращается к прежнему запуску и выбирает продолжение или полный повтор.

## Варианты

1. **Рекомендация:** исходные 20 Entry IDs. Новые две не добавляются автоматически. Начать обработку по текущей выборке Browser можно отдельным новым запуском.
2. Пересчитать выборку по актуальным данным/filter; в продолжение/повтор могут попасть новые Entries и исчезнуть переставшие соответствовать filter. Требуется явно показать изменившийся scope.

## Контекст

- [SQ-04](../04_SQ-04_interrupted-batch-retry/00_thread.md) разделяет продолжение необработанной части и явный полный повтор выбранного набора, но намеренно не выбирал snapshot selection vs filter recalculation.
- Для нового filtered batch уже принято использовать результат текущего filter expression с дополнительными eligibility conditions.
- Вариант 1 сохраняет состав IDs, а не разрешает обойти eligibility/Draft/lifecycle/ownership checks. Если Entry нельзя обрабатывать, действует общий skip/сообщение, а не принудительная мутация.
- Этот выбор не определяет автоматически frozen content snapshots/routineVersion или поведение при изменении конкретной Entry между запусками.
- Обычное продолжение сохраняет accepted already-processed semantics; полный повтор явно обходит только этот skip, не остальные guards.
- Точные manifest schema/paths, snapshot IDs и UI routing — техническая конкретизация после выбора.
- Короткие labels «Продолжить» / «Повторить всё» пока предложены; текущий вопрос о составе набора, а не их окончательном утверждении.
