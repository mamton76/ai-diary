## Вопрос

Разрешать ли обычный повтор AI-обработки той же routineVersion/input Revision, если предыдущий Run достоверно завершился ошибкой без успешного результата, или требовать Force rerun из-за самого факта прежнего запуска?

## Варианты

1. **Рекомендация:** failed Run без успешного результата не считается успешно already processed. Пользователь может обычным действием повторить обработку неизменной записи; обычный batch также не пропускает её только из-за этой ошибки. Ошибка остаётся в истории. Успешный Run с принятой/отклонённой proposal сохраняет прежние already-processed правила.
2. Даже failed Run блокирует обычную повторную обработку той же пары; для повтора требуется явный Force rerun.

## Контекст

- Run identity привязана к routineId/routineVersion/entryId/input Revision и outcome; новая Revision или routineVersion допускает обычный запуск.
- Принятие/отклонение успешно созданного proposal не отменяет факт выполнения Run; Force rerun уже доступен явно.
- Текущий выбор — о достоверном failure без успешного результата, а не о слепом повторе при неизвестном исходе, частично опубликованном результате или незавершённой операции. Такие случаи сначала требуют определения результата/reconciliation.
- Требование не разрешает параллельно создавать дубли уже queued/running обработки и не определяет operation ID/attempt schema.
- Draft eligibility и ownership/base checks сохраняются; эта политика не обходит требование успешного Save перед ручным Run.
- Automatic retry schedule, лимиты попыток, backoff, отменённые/частично успешные Runs и физический retry protocol требуют отдельной технической/продуктовой конкретизации.
- Вопрос не связан с NO_CHANGE manual Save или retry Save из FQ-03: здесь выбирается eligibility AI после failed Run.

## Обсуждение

Codex — (2026-10-18) Предлагаю разрешить обычный повтор после достоверной ошибки без результата, даже если Entry и routine не менялись. Ошибка не означает «уже успешно обработано». Для уже успешной обработки, включая отклонённое предложение, прежний Force rerun остаётся отдельным действием. Это рекомендация, ещё не принятое правило.

пользователь — (2026-10-18) «да»

Codex — (2026-10-18) Обычный повтор достоверного failure без результата разрешён. Сверка с [AQ-OPS-002](../../../04-open-questions.threads/37_AQ-OPS-002_safe-retries/00_thread.md) подтвердила отдельную принятую policy платных автоматических AI retries: eligibility не заменяет её и не разрешает слепой unknown-outcome rerun. Решение перенесено в обе спецификации, inventory/product baseline. Следующий независимый выбор — [готовые результаты при отмене batch](../03_SQ-03_batch-cancel-results/00_thread.md).

**Решение:** [принято] (2026-10-18) Достоверно failed AI Run без успешного результата не считается успешно already processed. Обычный повтор той же routineVersion/input Revision разрешён даже без изменения записи; обычный batch не пропускает запись только из-за такого failure. Неуспешный Run остаётся в истории. Для успешно выполненной обработки прежние already-processed правила сохраняются независимо от принятия/отклонения proposal; сознательный повтор успешной обработки использует Force rerun. Это правило не разрешает слепой повтор при неизвестном исходе и не меняет пользовательскую политику платных автоматических AI retries.
