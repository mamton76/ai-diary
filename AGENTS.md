# AI Diary — инструкции для агентов

Этот файл — короткая точка входа для ChatGPT/Codex и других агентов, работающих с репозиторием.

## Текущая фаза и источники

Актуальная целевая Web/API архитектура: `docs/architecture.md`; текущая последовательность работ: `docs/implementation-plan-web-mvp.md`. Требования и принятые продуктовые решения: `docs/baseline/`. Исторический Android/Firebase prototype не считать целевой архитектурой. Технические drafts не приравнивать к утверждённым схемам или завершённой реализации.

## Язык

Проектные документы и обсуждения по умолчанию вести на русском. Идентификаторы, API names, code symbols и названия технологий можно оставлять на английском.

## Project skills

Канонические skills:

```text
skills/
```

Перед работой с открытыми вопросами, спорными требованиями и design decisions **обязательно** прочитать и соблюдать:

```text
skills/discussion-threads/SKILL.md
```

Не полагаться на память чата о правилах discussion threads. Перед тем как взять PQ/SQ в работу, проверить canonical thread, его lifecycle state и claim. Тред со статусом `in_discussion` или `paused` и активным claim другим агентом не забирается.

## Личные данные в репозитории

Репозиторий планируется сделать публичным ([PQ-018](docs/baseline/04-open-questions.threads/56_PQ-018_portfolio-goal/00_thread.md)). Не добавлять в него тексты реального дневника, секреты, реальные идентификаторы календарей, папок и аккаунтов. Для тестов и примеров использовать синтетические данные.

## План

Текущие шаги и вопросы, которые нужно закрыть к каждому этапу: [`docs/plan.md`](docs/plan.md). Обновлять его в том же коммите, где закрывается шаг или решается вопрос. Статусы и формулировки решений в план не копировать: они живут в тредах и source-документах.

## Правила решений

- Не выдавать открытый вопрос за принятое решение.
- Не приписывать пользователю позицию, которой он не высказывал.
- Долгие спорные вопросы вести через discussion threads.
- Принятое решение переносить из thread в соответствующий source-документ.
- Историю пересмотренных решений не стирать.
- Если ChatGPT/Codex и Claude расходятся, сохранять обе аргументированные позиции и отдавать реальный выбор пользователю.

## Совместная работа Claude + Codex

Канонический протокол команды: [`docs/agent-team/README.md`](docs/agent-team/README.md). Перед началом работы с задачей прочитать `collaboration/README.md`, `orchestration/README.md` и конкретный `tasks/active/TASK-NNNN_slug/task.md`.

- Все значимые задачи и результаты сохраняются в переносимых файлах репозитория; GitHub Issues и PR — внешние интерфейсы, а не единственный источник истины.
- Для каждого задания обязателен Documentation Impact и обновление документации как часть Definition of Done; отсутствие изменений нужно обосновать.
- Для обсуждений внутри задачи — `discussion/threads/*.md`; `discussion/00_all.md` генерируется скриптом и не редактируется вручную.
- Создание Issue не разрешает запуск автоматически; не выполнять merge/deploy и не трогать реальные пользовательские данные без отдельного согласования.
- Текущий протокол описывает целевую оркестрацию; не утверждать, что облачные интеграции уже работают.
